# 技能：想法探索（pre-intake brainstorming）

## 定位

模糊想法的前置脑暴——**用户连 /intake 的三个基础问题（目标 / 时间 / 不做什么）都还答不清楚**时使用。产出是**一份草稿探索笔记**，不是需求文档，不进 backlog，不走 schema 校验。

## 触发场景

适用：
- "我想做一个 xxx 平台" / "要不要引入 xxx" / "类似 yyy 但不太一样"
- 同团队多人想法不一致，需要先收敛
- 知道要解决一类问题，但不知道有多少个切面

**不适用**（直接走对应流程）：
- 需求清楚 → `/intake`
- 纯技术选型 → 写 RFC 或 design
- 1:1 复刻已有产品 → `/intake` T4

---

## 执行流程（5 步，可中途停止）

### Step 1 · 问题框定（5 Whys 简版）

连问 3 层 why，把"要做什么"推到"要解决什么真问题"。

固定 prompt：
1. **为什么要做这个？当前痛点是什么，谁痛？**
2. **不做会怎样？现状能不能凑合？凑合的代价是？**
3. **已有方案为什么不够？**（买现成 / 开源 / 现有系统 / 人工处理）

如果用户连这 3 问都答不上来 → 建议先去调研，再回来探索。

### Step 2 · 维度拆解

根据问题类型，从通用维度库挑相关维度列出来，帮用户看到"这件事有多少面"。

**通用维度库**（AI 按场景挑选，不必全列）：

| 类别 | 典型维度 | 什么场景要想 |
|---|---|---|
| 生命周期 | 创建/修改/发布/下线/归档/版本 | 管理平台、工作台 |
| 角色权限 | 角色清单、粒度（行/列/资源/功能）、租户隔离 | 多人使用的系统 |
| 数据 | 数据源（单表/多表/跨库/API/流）、更新频率、缓存 | BI / 数据产品 |
| 交互 | 查看/筛选/排序/下钻/导出/订阅/告警/分享 | 前端展示型 |
| 运维 | 监控/告警/审计/日志/备份/容灾 | 平台化产品 |
| 扩展 | 自定义/插件/SDK/API 开放 | 平台化产品 |
| 性能 | 并发量、单次响应、批量量级、数据总量 | 所有 |
| 集成 | 上游数据来源、下游消费方、SSO / 消息 / 权限系统打通 | 嵌入型 / 平台型 |

Step 2 不要求每个维度都给答案——**列出来就是胜利**，让用户知道"原来我还没想过这个"。

### Step 3 · 候选方案对比

给 2–3 个**差异化路径**（不是"好中差"，而是侧重不同）。

**常见对轴**（AI 按场景选 1–2 轴即可）：
- 买 vs 开源 vs 自研
- 独立平台 vs 嵌入现有系统
- 配置化 vs 代码化 vs 两者混合
- 实时 vs 批量
- 一次建全 vs 按需演进
- 替代现有方案 vs 并存一段时间

输出模板：

| 方案 | 核心思路 | 适合 | 不适合 | 代价 |
|---|---|---|---|---|
| A | ... | ... | ... | ... |
| B | ... | ... | ... | ... |
| C | ... | ... | ... | ... |

### Step 4 · 边界与陷阱扫描

按"问题类型 × 通用坑清单"给出可预见的坑。

**管理平台类通用坑**：
- 权限漏洞（查看人偷偷编辑 / 越权）
- 并发编辑（两人改同一份，后提交覆盖前提交）
- 删除（软删 vs 硬删 / 误删恢复 / 关联资源级联）
- 审计追溯（谁改了什么 / 能不能回滚 / 保存多久）
- 列表性能（上千条时筛选、排序、分页）
- 导入导出（批量操作失败怎么办、事务边界）

**BI / 数据类通用坑**：
- 数据权限 × 功能权限交叉（能看见这张报表，但不该看到这个人的数据）
- 大查询拖垮库（慢查询、无索引、全表扫描）
- 数据口径不一致（同名指标、不同算法）
- 实时性期望 vs 实际能力不匹配
- 图表默认聚合逻辑错误（Sum / Avg / Count distinct）
- 数据变更与缓存失效

**平台化类通用坑**：
- 没 MVP 直接全功能（半年出不来，出来也没人用）
- 没想清楚现有方案的迁移路径
- 二期 / 三期空间没留（数据模型卡死）
- 租户 / 数据隔离事后加很痛
- 没想清楚"谁来填内容"（平台建好了没东西）

### Step 5 · 未知识别

列出目前还答不了的问题，明确**谁来答**和**不答的代价**。

| 问题 | 需要谁来答 | 不答会怎样 |
|---|---|---|
| 首批真实用户是谁 / 多少人 | 业务 / 产品 | 功能会做飘 |
| 数据量级预估（行 / MB / 增长） | 业务 / DBA | 架构选型错 |
| 和已有 xx 系统的权限怎么打通 | 架构 | 后期要返工 |
| 预算和时间窗口 | 老板 | 方案选错 |

## 输出物

落盘到 `docs/_exploration/EXPLORE-YYYYMMDD-<slug>.md`。

**关键约束**：
1. **不走 schema 校验** — 产出是草稿
2. **不分配 need_id** — 不是需求
3. **不计工作量** — 不走 XS/S/M/L/XL
4. **可中途停止** — 用户觉得 Step 2 够了就停，不强制走完
5. **可丢弃** — 探索后决定不做也是好结果，移到 `docs/_exploration/dropped/`

## 与其他阶段的关系

```
想法模糊
   │
   ▼
/explore ──▶ docs/_exploration/EXPLORE-xxx.md（草稿）
   │
   ├── 想清楚了 ──▶ /intake（几乎秒过 T3/T4 档位）
   ├── 要验证 ──▶ POC / 调研 → 回到 /explore 继续
   └── 不做 ──▶ 归档到 _exploration/dropped/
```

`/explore` **不是** `/intake` 的替代，而是前置。走过 `/explore` 的需求进入 `/intake` 时可以直接把探索笔记当作 `background` 字段的依据，填写效率大幅提高。
